# 账号定位

本 Skill 负责账号级 Profile，不负责单篇创作、研究、发布或复盘。

## 职责

- 读取、补全和更新账号定位、目标用户、内容领域、风格、边界与参考账号。
- 输出可供诊断、策略、创作和复盘消费的 Profile；不创建内容 Run，不执行对外动作。

## 输入与输出

- 输入：本轮已选账号、现有 Profile、用户明确提供或确认的账号事实。
- 输出：本轮使用或更新后的 Profile、仍缺失字段，以及对后续阶段的约束。

## 流程

1. 从本轮账号上下文读取用户已选择的目标账号；小红书使用当前连接器稳定
   accountId，公众号使用当前连接器 APPID。没有已选账号时停止，不要求用户补充定位。
2. 使用目标账号的 AccountRef 调用 `content_profile_get` 读取现有定位。
3. 已有定位且足以完成本轮任务时直接使用，不要求用户重复提供或确认。
4. 定位缺失或缺少本轮目标必需信息时，按“授权”章节处理前台补全或自动化跳过。
5. 用户明确确认新增或修改内容后，使用 `content_profile_patch` 更新。
6. 返回本次使用或变更的定位、仍缺失字段和对后续内容阶段的约束。

## 授权

- 本 Skill 不执行发布、互动等对外动作，无需外部动作授权。
- 前台对话补全或修改 Profile 时，必须调用 `AskUserQuestion` 只询问必要字段；只有用户明确
  确认的事实才能持久化。
- 自动化任务不得调用 `AskUserQuestion` 或等待用户补充信息；跳过缺失字段并把影响交给下游阶段说明。

## 失败与交接

- 未选择账号时停止，不要求用户补充定位。
- 读取或写入失败时保留原 Profile，不把未持久化内容当作已生效事实。
- 成功后把 Profile 和缺失字段交给发起本 Skill 的诊断、策略、创作或复盘阶段。

## 边界

- Profile 是用户明确事实，优先级高于 Playbook 和历史表现。
- 本轮账号上下文只提供已选账号事实，不代表账号定位已存在；定位状态必须通过
  `content_profile_get` 判断。
- 不根据单次内容表现自动修改 Profile。
- 不创建 Run，不写 History、Playbook 或 review。
